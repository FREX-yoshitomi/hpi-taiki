HPI — Human Programming Interface

俺の人生を、
ひとつのインターフェースに。

X の投稿も、GitHub のコミットも、昨日の睡眠も、今朝聴いた曲も—— バラバラのサービスに散らばった俺・吉富大起の人生の痕跡を、手元のコードから ひとつのAPIで触れるようにする。これは、その構想と設計。

Phase 4 — ダッシュボード稼働中 吉富大起 / FREX 2026 — inspired by karlicoss/HPI

※ データのダッシュボードはプライバシー保持のため手元(ローカル)で稼働します。

00

これは何か

What

HPI = Human Programming Interface。 自分の人生のデジタルな痕跡を、各サービスの檻から引き剥がして、手元に集約し、 my.x.tweets() のように プログラムから統一的に触れるようにする仕組み。

karlicoss の HPI(「自分の人生をPythonパッケージにする」)に着想を得て、 吉富大起という人間のための実装をゼロから組み立てる。GUI でも、誰かのアルゴリズムでもなく、 自分のコードで自分のデータに向き合うための土台。

01

なぜ作るのか

Why

俺のデータは20以上のサービスに散らばっていて、横断できない。これが日常的に困る。

  • サイロに閉じ込められている — LINE の会話を3年前まで遡れない。GitHub の活動とカレンダーの予定を突き合わせられない。
  • サービスの UI に支配されている — 各サービスの「おすすめ」や狭い検索窓からしか、自分のデータに触れられない。
  • 横断検索ができない — 「あの話、どこで誰と喋ったっけ?」が、Slack・LINE・X・メモを全部手で探すしかない。
  • 記憶が外部に預けっぱなし — しかも各社のさじ加減でいつ消えるか分からない。自分の痕跡なのに、自分でコントロールできない。

デジタルな痕跡は、俺が何を考え・何をして・何に時間を使ったかの記録——つまりアイデンティティの一部だ。 なら、それは俺がコントロールすべきだし、コードで自由に触れられるべきだ。記憶と集計はコンピュータに任せ、判断と創造は自分がやる。

02

設計思想

Principles
▌LOCAL-FIRST

ローカルファースト

クラウドに常時接続しない。各サービスから定期的にエクスポート → 手元に集約 → ローカルのデータだけを読む。速い・堅い・オフラインでも動く。多少のラグは許容する。

▌MODULAR

モジュール式

データ源ごとに独立したモジュール。必要な分だけ繋ぐ。ひとつが壊れても他に波及しない。新しい源は my.<name> を足すだけ。

▌CODE IS UI

コードがインターフェース

触る対象は GUI ではなく Python オブジェクト。スキーマの硬さより、コードの柔らかさで現実の揺らぎ(形式変更・欠損)を吸収する。

▌PRIVATE BY DESIGN

プライバシーは自分の手に

データは外に出さない。手元に置く。共有するのはコードだけ。個人情報を含む設定とデータは .gitignore で隔離する。

03

アーキテクチャ

Architecture

3層に分ける。各層は疎結合で、下から上へデータが流れる。

LAYER 1

エクスポート層 export

各サービスからデータを取り出す。公式エクスポート(X アーカイブ / Google Takeout)・API・スクレイピング・手動。cron で定期実行して自動化していく。

↓
LAYER 2

集約層 local store

取り出した「生データ」を手元に貯める。JSON / SQLite / ファイルそのまま。~/data/<source>/ 以下に源ごとに整理。ここはまだ加工しない。

↓
LAYER 3

アクセス層 my.* package

生データを読み、正規化した Python オブジェクトを返す。my.* 名前空間。「どこにあるか・どう読むか・エラー処理・キャッシュ」を内部に隠し、上のコードは綺麗な API だけを見る。

05

統一API: my.* の設計

The Interface

すべてのアイテムは最小共通項として dt(発生時刻)・source・kind・text・raw を持つ。これがあるから横断とタイムライン化ができる。

~/hpi-taiki — python
import my.x, my.github, my.music
from collections import Counter
from datetime import date

# 直近の自分が一番ツイートしてる時間帯トップ3
Counter(t.dt.hour for t in my.x.tweets()).most_common(3)

# 今日のサマリー: コミット数 / 聴いた曲数
today = date.today()
commits = [c for c in my.github.commits() if c.dt.date() == today]
songs   = [m for m in my.music.scrobbles() if m.dt.date() == today]
print(f"今日: {len(commits)} commits / {len(songs)} 曲")

横断は「全部の源を dt で並べる」だけ:

my/timeline.py
import my.x, my.github, my.slack, my.youtube
from itertools import chain

# 全データ源を1本の時系列に統合 = 「俺の人生のログ」
events = sorted(
    chain(my.x.tweets(), my.github.commits(),
          my.slack.messages(), my.youtube.watched()),
    key=lambda e: e.dt,
)
for e in events[-10:]:
    print(e.dt, e.source, "|", e.text[:60])
06

これで何ができるか

Use cases

A横断タイムライン

全データ源を時系列に統合した「俺の人生のログ」。あの日、何をして・誰と話して・何を聴いていたか。

B全文検索

過去の全チャット・メモ・投稿を、ひとつの検索窓で。サービスを跨いで「あの話」を一発で。

Cライフログ分析

睡眠 × 生産性(コミット数)× 気分の相関。データドリブンに自分のコンディションを理解する。

D記憶の補助

「このURL前にいつ見た?」をブラウザ上で。痕跡を辿れる外部記憶(promnesia 的)。

E年次レビュー

1年の活動を自動で振り返り。読んだ本・聴いた曲・行った場所・書いたコードの総括。

FAIへの文脈供給

正規化済みの自分データを、自作 AI(FREX の各プロダクト)の文脈として安全に渡す土台。

段階的に作る

Roadmap
PHASE 0 ✓

構想と土台

この構想ページ + my/ パッケージの骨組み(共通スキーマ Item と my.timeline)。設計を言葉と型で固めた。

PHASE 1 ✓

最初の1本を通した — GitHub

gh api でイベントとコミットを取得 → data/github/ に集約 → my.github.events() / commits() が実データで動作。エクスポート→集約→アクセスの全層が貫通。

PHASE 2 ✓

横断の核

2本目の源 my.git(ローカルリポジトリ)を追加し、my.timeline で github × git の横断を実証。残る源(X / Slack 等)は本人のエクスポート待ち。

PHASE 3 ✓

検索 / 自動化

全データ源を横断する全文検索 my.search、一括更新 tools/refresh.py を実装。定期実行の登録は任意。索引化は今後。

PHASE 4

可視化 / ダッシュボード現在地

dashboard.html(手元で稼働) が稼働 — 活動ヒートマップ・源別/種類別の内訳・検索付きタイムライン。年次レビューや AI への文脈供給へ拡充していく。
